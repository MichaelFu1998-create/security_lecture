Broken Access Control (IDOR)

Section 2 · insecure direct object reference
{% include "_toggle.html" %}

// what is it?

The app looks up a record straight from an id in the URL without checking whether it belongs to you. Change the id and you read someone else's data.

// try it

You are logged in as alice (user #{{ current_id }}). Request a profile by id:
user_id=1 (you) user_id=2 user_id=3
{% if result %} {% if result.denied %}
⛔ 403 Forbidden — you can only view your own record.
{% elif result.user %}
{% if result.other %}😈 You accessed {{ result.user['username'] }}'s private record — that isn't you!{% else %}Your own record:{% endif %}
username: {{ result.user['username'] }}
email: {{ result.user['email'] }}
bio: {{ result.user['bio'] }}
{% else %}
No such user (#{{ result.uid }}).
{% endif %}

// under the hood

Request:
GET /access-control?user_id={{ result.uid }}
{% if mode == 'vuln' %} 
row = db.execute("SELECT * FROM users WHERE id = ?", (user_id,))   # no ownership check!
{% else %} 
if requested_id != session_user_id:
    abort(403)     # you may only read your own record
{% endif %}
{% endif %}

// the fix

Never trust an id from the URL for access decisions. Derive identity from the session and check ownership on every request (authorization, not just authentication).
